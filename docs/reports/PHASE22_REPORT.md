После статической индексации Runtime в фоновом потоке рассчитывает SHA-256 отпечаток и проверяет локальный снимок. При синхронизации с импортированной сборкой редактор проверяет путь источника, Minecraft/Forge и наличие известных установленных модов с их версиями. Отпечаток вычисляется до и после сбора. Если входные файлы поменялись, новая версия снимка отклоняется. Сбор без импортированного проекта по-прежнему сохраняет переносимый `.mresnapshot`.

Отпечаток включает Minecraft, загрузчик и его версию, ID и версии модов и хэши файлов относительно корня игры. Входы включают JAR, datapacks, KubeJS, ресурспаки, конфигурации и порядок выбранных ресурспаков. Из папок локальных миров учитываются только datapacks и serverconfig. Меняющийся при запуске файл сессии Companion и служебные журналы/кэш KubeJS исключены.

Ключ базы не зависит от абсолютного пути. Когда точного совпадения нет, хранилище ищет прежний снимок по сохранённому источнику как подсказке и показывает `STALE`. Доступ к устаревшему кандидату через API требует явного согласия вызывающей стороны. `COLLECTING` относится к незавершённой операции в Runtime. Также различаются `NOT_AVAILABLE`, `AVAILABLE`, `INCOMPATIBLE` и `CORRUPTED`.

## SQLite

Путь по умолчанию — `%LOCALAPPDATA%/MinecraftRecipeEditor/cache/<sha256>/snapshot.db`. Учитывается существующий `MRE_DATA_HOME`. Драйвер — [Xerial SQLite JDBC 3.50.3.0](https://github.com/xerial/sqlite-jdbc/releases/tag/3.50.3.0).

| Таблица | Содержимое |
| --- | --- |
| `snapshots` | Поколение, отпечаток, ID снимка, версия DTO, сведения о среде, диагностика и ожидаемые размеры наборов |
| `registry` | Items, Blocks, Fluids, Recipe Types и Serializers |
| `tags`, `recipes`, `mods`, `materials` | Отдельная строка на запись. Полный payload хранит модовые свойства, метаданные и происхождение |

Схема помечена `application_id` и `user_version=1`. Данные упорядочены составным ключом по поколению и номеру строки. Ограничение уникальности по поколению и ключу записи защищает от дубликатов. Чтение проверяет SQLite `quick_check`, ожидаемое число строк, последовательность, лимиты и DTO. Неизвестная схема отклоняется. Поддерживаются обе версии runtime DTO существующего протокола.

Публикация добавляет поколение одной транзакцией. Пока транзакция не подтверждена, читатель видит предыдущий снимок. Ошибка записи или неполный DTO не заменяют рабочую версию. Старые поколения и каталоги старых отпечатков сохраняются.

## Границы шага

Автоматическое применение SQLite-снимка к каталогу при открытии проекта, выбор устаревшего снимка в интерфейсе, дисковый кэш PNG и офлайн-редактирование относятся к следующим шагам. Полная загрузка DTO сейчас читает записи в память. Запросы с пагинацией будут нужны для офлайн-каталога. Совпадение отпечатка подтверждает набор файлов, а не активный мир или состояние уже запущенного сервера. Текущий протокол не передаёт идентификатор мира и хэши файлов, фактически загруженных в JVM.

Git push, merge и Release в рамках этого прохода не выполнялись.
