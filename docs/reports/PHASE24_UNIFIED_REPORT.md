# Phase 24 — Единый каталог и редактор рецептов

Рабочая ветка `feat/phase-24-universal-runtime-recipe-editor`. Версия приложения `1.1.4-alpha`.

## Причины

- `RecipeBrowserView.showSource()` раньше оставлял общую панель инструментов и фильтров на месте, а её рабочую область заменял отдельным `RuntimeRecipeBrowserView` со своей таблицей и вторым набором фильтров.
- При выборе Runtime метод отключал целиком `ToolBar`. Локальный Edit второго представления требовал одну совпадающую статическую запись. В `RecipeEditorService` тоже не было базового определения для рецепта, обнаруженного только в Runtime. Простое включение кнопки привело бы к ошибке при сохранении.
- Вторая таблица использовала Recipe ID и выводила нормализованные свойства как текст. Она обходила общий рендерер, разрешение имён по результату и сервис изображений.

## Реализация

Один виртуализированный каталог обслуживает All, Static, Runtime, Project и Effective. Фильтры и таблица остаются на месте при смене источника. Наблюдаемое определение в All имеет приоритет. Если полный снимок не содержит статический рецепт, запись по-прежнему доступна через Static, но не возвращается в Effective. Поиск по большим каталогам использует отменяемую фоновую задачу и переиспользует подготовленные поисковые строки.

Правая часть использует общие вкладки Recipe, Raw JSON, Source и Diagnostics. В Raw JSON можно независимо выбрать текущий JSON проекта, нормализованные свойства из снимка и найденные статические кандидаты. В визуальной вкладке работают существующие компоненты раскладки, локализации, слотов и общего сервиса изображений. Основным результатом выбирается предмет, затем жидкость. Для динамического или неизвестного результата используются доступные сведения о типе. У графических слотов редактора тот же Ingredient Picker и язык, что у каталога.

Проверенный адаптер преобразует наблюдаемое состояние в отдельную модель сериализатора. Сохранение создаёт запись в существующем ChangeSet и меняет только каталог проекта. Для наблюдаемого базового определения ChangeSet сохраняет источник, хеш и исходную проверенную проекцию. Сохранённое изменение блокируется до появления совпадающего снимка. При загрузке подходящего снимка оно становится доступно, при изменении проекции остаётся заблокированным. Экспорт сверяет базу и текущий экземпляр сборки. Для удаления используется проверенная стратегия KubeJS с точным Recipe ID.

## Проверки

- `gradlew.bat clean build` и отдельный `gradlew.bat test` прошли на Java 21 в изолированном каталоге с локальным Gradle-кэшем. Прошло 387 unit-тестов и 113 интеграционных тестов. Два unit-теста символических ссылок пропущены в Windows. Проверка архитектуры нашла 12 модулей без циклов.
- Запущенная сборка ISG аутентифицировалась по протоколу 1 с Companion 0.1.0. Запрос свежего снимка завершился `SYNC_FAILED: IllegalStateException: Collection busy` на `GET_REGISTRIES`. Игра продолжила работать. Файлы сборки не менялись и экспорт в игру не применялся.
- Офлайн-тест на сохранённом снимке ISG `e0fb68a7-32a3-444f-a519-b5d5b883bfb6` прошёл. Каталог из 98 937 рецептов подготовлен за 7,20 с. Для 19 953 записей тест со статически пустым индексом построил проверенные проекции. Реальный рецепт `ad_astra:blasting/desh_ingot_from_blasting_deepslate_desh_ore` показывает `Desh Ingot` / `Дешовый слиток`, параметры плавки 100 тиков и 0,1 опыта. Изображение результата берётся из PNG Ad Astra, SHA-256 которого совпадает с метаданными снимка.
- В офлайн-тесте изменены вход на реально зарегистрированный `ad_astra:moon_desh_ore` и выход на `minecraft:gold_ingot`. Изменения сохранились в ChangeSet, план экспорта сформировал Datapack JSON с обоими изменениями, а исходные данные снимка остались прежними. На том же наборе проверены девять позиций форменного крафта для титанового лома GTCEu с NBT-результатом и доступность для просмотра зарегистрированных типов Assembler и Chemical Reactor. Скриншот JavaFX записан в `.manual-tests/phase24/unified/offline-desh.png`.

## Ограничения

- Непроверенные или неоднозначные Runtime DTO доступны для исследования. В частности, старый снимок может содержать Smithing без точных ролей и GregTech без содержимого машинных слотов. Там, где сведения ограничены, отображаются только известные поля.
- Смена типа и специализированный экспорт GregTech по-прежнему ограничены проверенным профилем GTCEu 7.1.4. Совместимый снимок должен содержать реальные пределы слотов. В вашей сборке с GTCEu 8 авторство и экспорт машинных рецептов остаются недоступны.
- Общий кэш сохраняет нативное превью проверенного снимка при отключении Companion в текущем сеансе редактора. При новом запуске редактор может повторно построить превью из доступных локальных моделей и текстур.
