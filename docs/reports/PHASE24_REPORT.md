# Phase 24 — Runtime Recipe Types и редактор Vanilla

Ветка `feat/phase-24-universal-runtime-recipe-editor`, база Phase 23 (`59bc9ee`), которая уже вошла в `origin/master` через `290252f`. Версия приложения `1.1.4-alpha`.

## Аудит

| Компоненты | Фактическая граница |
| --- | --- |
| Companion, RecipeManager, Registry, Serializer | Forge передаёт зарегистрированные типы и сериализаторы раздельно. Загруженные рецепты связывают конкретный тип с конкретными сериализаторами. Один тип может иметь несколько сериализаторов. GTCEu дополнительно использует категории и прокси. |
| RecipeDefinition, Runtime Recipe, RecipeChangeSet | Статическая модель хранит payload и provenance. Runtime DTO сохраняет serializer ID, адаптер, свойства и диагностику. Нормализованный DTO не гарантирует исходный JSON. Операции редактора пишут отдельный ChangeSet. |
| Реестр и адаптеры | Каталог объединяет регистрацию с наблюдениями, включая нулевые типы. Учитывает целевое окружение и проверенные пары типа и сериализатора. Namespace виден отдельно от источника объявления. |
| JavaFX, JEI/EMI и Ingredient Picker | Новые Vanilla-черновики используют существующие редактор, layout и Ingredient Picker. Форма свойств выбирает контролы по явной схеме Vanilla, неизвестные параметры остаются в JSON. |
| Snapshot и Offline | SQLite добавляет `recipe_types` в той же транзакции. Базы без дополнительной таблицы и переносимые снимки выводят каталог из сохранённых записей. Runtime может открыть SQLite-снимок по актуальному отпечатку без подключения. |
| Экспорт | Допуск к экспортам реквизитов отдельного рецепта по-прежнему проверяют ExportPlanner и адаптеры KubeJS, Datapack и CraftTweaker. Наличие DTO или сериализатора не делает произвольный `event.custom` проверенным. |

## Редактор

В `Runtime → Recipe Types` есть поиск по ID, поиск по сериализатору и фильтр доступного создания. Из выбранного типа можно открыть шаблон подтверждённого Vanilla-сериализатора, когда снимок применён к совместимому проекту.

Создание предлагает наблюдаемые сериализаторы из существующих Vanilla-шаблонов. `crafting` может содержать обычные и специальные сериализаторы. Специальные сериализаторы без проверенного шаблона исключены из меню. Поддерживаемые новые черновики проходят существующую валидацию и записываются как `CREATE`.

Копирование нормализованного Vanilla в новый ID поддерживает shaped, shapeless, smelting, blasting, smoking, campfire cooking и stonecutting. Оно требует подтверждённого адаптера, известной формы ингредиентов и результата без NBT. Исходный снимок остаётся в хранилище. Неизвестные поля, варианты, отсутствующие данные и динамический результат блокируют такое копирование. Существующее редактирование, удаление и копирование статических источников сохранены. Для непосредственно runtime-only UPDATE и DELETE нужен отдельный контракт происхождения и экспорта.

## GTCEu и остальные моды

В реальном установленном JAR GTCEu `8.0.0-SNAPSHOT+e24b238` изучены публичные типы и байткод `GTRecipeSerializer.CODEC`, включая поля условия, продолжительности, данных и действия KubeJS. У `Content` в этом билде методы записи вместо полей старой версии. Отдельный путь Companion под точный билд 8 сохраняет вложенный результат публичного кодека, явно маркирует его как данные для просмотра и использует существующий обход категорий/прокси. Профиль 7.1.4 сохранён.

Команда независимой сборки Companion на Java 17 прошла. Обновлённый JAR остался в выходной папке Companion. Для живой проверки нового профиля потребуется установить JAR в закрытую игру, затем запустить клиент. Текущая игра и её существующее соединение с Desktop оставлены в работе. Новый GTCEu-профиль ещё требует живой проверки. Операции машинного редактора и экспорт KubeJS для GTCEu 8 не разрешены.

Остальные моды включаются по регистрации и загруженным рецептам независимо от namespace. Дополнительные схемы Create, Mekanism, Botania, Ad Astra и NuclearCraft должны опираться на конкретный проверенный сериализатор и тест экспорта. Прежние интеграции сохранены.

## Проверки

- Desktop `clean build` успешно за 3 мин 16 с, отдельный `test` успешно за 1 мин 6 с. Финальный `build test` прошёл за 1 мин 11 с. 384 unit-теста, 2 пропуска окружения. 111 интеграционных тестов, ошибок нет. Открытый Desktop удерживал JAR в стандартном `build`, поэтому Gradle использовал отдельные выходные каталоги из основной рабочей папки. Архитектурные тесты теперь читают каталог классов, указанный Gradle.
- Тесты проверили каталог пустых/наблюдаемых типов, serializer ID и неизвестный источник, сохранение и чтение SQLite, чтение старой базы, валидацию нового Vanilla-рецепта и Undo/Redo, отказ при неполных данных и NBT, выбор схемы известных полей. Отдельный внешний тест каталога SQLite прошёл на реальном снимке.
- Независимый `build` Companion на Java 17 прошёл за 1 мин 3 с. JAR `minecraft-companions/forge-1.20.1/build/libs/mre_companion-forge-1.20.1-0.1.0.jar`.
- Новая JavaFX-сборка и новый Companion не проверялись вручную в текущей живой сессии. Доступность игрового процесса и действующего подключения подтверждена. Установку нового Companion, запуск второго Minecraft и перезапуск игры не выполнял.

Универсальные схемы произвольных модовых полей, поддержка записи runtime-only рецептов и GTCEu 8 KubeJS требуют последующих проверок. Полный набор критериев Phase 24 ещё не закрыт.
