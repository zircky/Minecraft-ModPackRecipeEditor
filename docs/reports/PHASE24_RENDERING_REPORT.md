# Phase 24 — Рендеринг предметов и постоянный кэш

Ветка `feat/phase-24-universal-runtime-recipe-editor`, версия приложения `1.1.4-alpha`.

## Диагностика

| Наблюдение | Подтверждённая причина |
| --- | --- |
| Плоские кабели, провода и трубы GTCEu | В снимке ISG это `MaterialPipeBlockItem` с режимом `SAMPLE`. Ранее общий fallback мог показывать любой известный спрайт как иконку, включая грань объёмной модели. |
| Blood Altar | В реестре ISG зарегистрирован `bloodmagic:altar`. Его item-модель наследует block-модель `bloodmagic:block/bloodaltar` с загрузчиком `forge:obj`. Статический JavaFX-рендерер этот загрузчик не поддерживает. Снимок содержит только `SAMPLE`, по которому нельзя определить пропорции нативного PNG. |
| Пластина, кольцо и слиток GTCEu | Снимок содержит `LAYERS` для всех трёх. Обычный файловый поиск моделей не восстанавливает все генерируемые модели материала. Резерв по подтверждённым слоям клиента теперь допустим для плоского предмета, если доступны соответствующие PNG и хеши. |
| Resource ID вместо имени | В старом снимке русские названия этих форм уже записаны. При выборе другого языка и отсутствии английского перевода интерфейс показывал ID, игнорируя единственную подтверждённую локализацию. Опознанное имя сохраняется в исходной локали. |
| Unknown result у Blood Magic | Статический адаптер ранее не распознавал `bloodmagic:array`. В установленном JAR есть отдельные рецепты с результатом, например Air Sigil, и массивы с эффектом, где `minecraft:bedrock` используется как служебное значение. Для массивов с эффектом показываются тип и эффект. Исходный JSON сохранён. |

## Реализация

- Items, Fluids, Materials, Recipes и панели выбора используют общий `InventoryPreviewProvider`. Для блоков нативный запрос использует только однозначно зарегистрированный BlockItem. ImageView сохраняет пропорции и прозрачность и отключает сглаживание. Тег остаётся тегом. Команда контекстного меню переключает индексированный элемент только для превью.
- Для привязанного снимка порядок поиска — проверенная дисковая запись, нативный рендер клиента, статическая модель, подтверждённые плоские слои или placeholder. Для `SAMPLE` отдельная грань больше не подставляется вместо модели. Нативный рендер идёт через существующий `GuiGraphics.renderItem` в прозрачном framebuffer с глубиной. Forge ограничивает работу одной задачей на render tick, PNG кодируется отдельно.
- `item-previews-v1` находится в локальном кэше приложения рядом с SQLite. Каждый файл соответствует ID, варианту, хешу NBT, разрешению и версии рендера в области версии Minecraft, fingerprint сборки и ID снимка. Запись содержит контекст ресурспаков, контрольную сумму и ограниченный PNG. Повреждённые и устаревшие записи диагностируются отдельно. Одна нативная запись переиспользуется для Item и связанного BlockItem. SQLite рецептов и проекты сохраняют прежний формат.
- В Runtime → Preview Cache доступны сбор отсутствующих, повтор неудачных, полное обновление, пауза, продолжение и отмена. Охват — зарегистрированные стандартные ItemStack в 64 px. Запросы идут пачками до четырёх, с задержкой, ограничением времени и одной повторной попыткой при ошибке запроса. Каждый завершённый PNG записывается сразу. Успешная запись сохраняется при ошибке повторного рендера в том же контексте.

## Инвентаризация и ограничения

- В доступном снимке ISG 29 442 записи ITEM. В новой области дискового кэша на момент аудита было 0 сохранённых, 29 442 отсутствующих и 0 повреждённых записей для стандартных стеков на 64 px. SQLite содержит реестры и метаданные спрайтов. Четыре диагностических PNG на 128 px из прежних тестов прошли проверку CRC. У них нет полного ключа сохранения, автоматический импорт не выполнялся.
- В реестре обнаружены алюминиевые провода, кабели, жидкостные трубы, руда, пластина, кольцо, слиток и инструменты. Записи алюминиевых Item Pipes в проверенном снимке отсутствуют.
- Живое сравнение иконок Blood Altar, Furnace и GTCEu с инвентарём — **NOT VERIFIED**. На момент проверки Minecraft и слушатель текущего Companion не обнаружены. Исходный PNG алтаря на этом запуске не получен.
- Просмотр `bloodmagic:array` доступен из проверенного статического JSON, в том числе при наличии сопоставленной записи Runtime. Из одних неполных Runtime-метаданных результат массива не выводится.

## Проверки

- `clean build` и отдельный `test` для Desktop на Java 21 прошли. 388 unit-тестов и 116 интеграционных тестов прошли. Два unit-теста символических ссылок пропущены в Windows.
- Интеграционный тест использует аутентифицированное соединение с тестовым сервером Companion и синтетическим PNG. Проверены сбор отсутствующих, повторный пропуск уже собранных, чтение новым экземпляром сервиса без подключения, прозрачность, разные NBT-контексты, обнаружение и замена повреждённой записи, игнорирование `SAMPLE` и использование подтверждённых `LAYERS`. Это подтверждает путь передачи и хранения, а не визуальную точность нативных моделей в игре.
- Forge Companion для 1.20.1 собран на Java 17. Протокол и исходники рендера Companion в этой задаче не менялись.
- Офлайн-аудит на снимке ISG с 98 937 рецептами прошёл. В JavaFX отображается превью результата Desh. Скриншот находится в `.manual-tests/phase24/render/offline-desh.png`.
